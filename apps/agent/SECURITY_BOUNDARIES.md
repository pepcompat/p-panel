# pPanel Agent — security boundaries

This file lists every boundary the agent enforces on a managed host, how it is
enforced, and which tests and fuzzers cover it. The Center is **not** trusted:
every job is re-validated on the agent. Specs: `docs/AGENT_PROTOCOL.md`,
`docs/SECURITY_THREAT_MODEL.md` (TB5/TB6), brief §3 and §14.1. Last full review:
P7.02 (2026-11-23).

Running the checks:

```sh
cd apps/agent
gofmt -l . && go vet ./... && go test ./... -race -cover -count=1
# a fuzzer (repeat per name below); crashers land in <pkg>/testdata/fuzz/<Fuzzer>/ and are replayed by go test
go test ./internal/<pkg> -run='^$' -fuzz='^FuzzX$' -fuzztime=60s -fuzzminimizetime=10s
govulncheck ./...
pnpm --filter @ppanel/shared-contracts test:fuzz      # TS validators (fast-check), FC_NUM_RUNS=20000 for longer
```

## 1. Typed, allowlisted jobs only (no generic execution)

| Boundary                      | Enforcement                                                                                                                                                                                                                                                                                                                 | Tests / fuzzers                                                                                                                                                                      |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Only registered job types run | `jobs.Registry` is a fixed map filled by `handlers.RegisterAll`; unknown, mis-cased or padded types → `REJECTED_UNKNOWN_TYPE`. There is no shell or "run command" handler.                                                                                                                                                  | `TestRegistryIsAllowlist`, `TestGrantBoundariesRejectedBeforeAck`, `FuzzGrantValidate`                                                                                               |
| Grant identity                | `serverId` must equal the enrolled id exactly (`REJECTED_WRONG_SERVER`). jobId must match `^[A-Za-z0-9][A-Za-z0-9_.:-]{0,127}$`. The lease token must be printable and ≤ 1 KiB. A grant without jobId, lease token or expiresAt → `REJECTED_INVALID_GRANT`.                                                                 | `TestUnknownTypeWrongServerInvalidParams`, `TestGrantBoundariesRejectedBeforeAck`                                                                                                    |
| Expiry                        | `expiresAt + 30 s` must not be in the past (`REJECTED_EXPIRED`).                                                                                                                                                                                                                                                            | `TestExpiredGrantRefusedNotExecuted`, `FuzzGrantValidate`                                                                                                                            |
| Replay                        | A bounded on-disk cache of 1000 jobIds is marked _started_ durably **before** execution. A known jobId, even with another type or lease, gets the cached result and never runs again. A job that started but did not finish before a restart → `AGENT_INTERRUPTED`.                                                         | `TestDuplicateJobNotReexecutedAcrossRestart`, `TestStartedButUncompletedJobNeverReexecuted`, `TestReplayedJobIDAfterRestartDifferentType`                                            |
| Params shape (every type)     | `jobs.CheckParamsShape`: a JSON object (JSON whitespace only), ≤ 12 MiB, nesting depth ≤ 32, ≤ 200 000 values, no NUL in any string or key, no trailing data. Each typed decoder then runs strict decoding: unknown fields are rejected at every level, and JSON `null` is rejected where the zod schema does not allow it. | `TestGrantBoundariesRejectedBeforeAck` (oversized, giant array, deep, NUL, unknown and nested-unknown fields, non-object), `FuzzParamsShape` (crashers `{` and `{}\v` kept as seeds) |
| No side effect before ack     | `Validate` (decode + `Preflight`) is pure. Ack happens only after validation succeeds; a failed ack (e.g. 409) means the job never runs.                                                                                                                                                                                    | `TestAckConflictNotExecuted`, the agent tests check handler invocations = 0 and acks = 0                                                                                             |

## 2. Process execution (`internal/execx`)

| Boundary                        | Enforcement                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Tests / fuzzers                                                                                                                                                                                                                         |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| No shell, fixed argv            | `exec.Command(absBinary, args...)`. The binary path must be clean and absolute, and binaries are resolved only from the fixed system dirs (`Find`). Args containing NUL, CR or LF are refused; at most 512 args of ≤ 8 KiB each.                                                                                                                                                                                                                                 | `TestRejectsRelativeAndUnsafe`, `TestOutputCapAndArgvNotShell`, `TestArgvBounds`                                                                                                                                                        |
| Option injection                | Every value the Center controls is either after `--` (systemctl unit, restic paths) or the value of a fixed flag, and validators refuse a leading `-`: unit regex starts `[A-Za-z0-9]`, restic excludes, DB name/user, tags, snapshot ids are hex, repo URLs start with `rest:`/`http`, git URLs start with a scheme, commit SHAs are hex. nginx and `nginx -t` take no Center values.                                                                           | `TestServiceRestartOwnedUnitFixedArgv`, `TestArgvNoOptionInjection`, `TestPathsBackupArgvEnvAndSummary`, `TestDBBackupDumpArgvAndManifest`, `FuzzDecodeBackupParams`, `FuzzDecodeBuild`/`FuzzDecodeInspect` (`-oProxyCommand`, `ext::`) |
| Environment                     | Fixed minimal env plus an allowlist of exact keys (`ExtraEnvKeyRe`). Command-executing variables are refused: `GIT_SSH*`, `GIT_EXEC_PATH`, `GIT_PROXY_COMMAND`, `GIT_CONFIG_PARAMETERS`, `*_COMMAND`, `*_FILE`, `LD_*`/`DYLD_*`, `PATH`. Values are pinned where it matters (`GIT_ASKPASS=/bin/false`, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_ALLOW_PROTOCOL` ∈ https/git). `GIT_CONFIG_KEY_n` may only name non-executing config keys. Duplicate keys are refused. | `TestEnvAllowlistBypass`, `TestRunCmdEnvAndDir`, `FuzzCheckEnv`                                                                                                                                                                         |
| Output caps                     | stdout is capped at `MaxOut` and stderr at 64 KiB; the rest is drained and the result is flagged `Truncated`.                                                                                                                                                                                                                                                                                                                                                    | `TestOutputCapsStdoutAndStderr`                                                                                                                                                                                                         |
| Timeouts kill the process group | Each child runs in its own process group (`Setpgid`). A timeout or cancel signals the **group** (SIGKILL, or SIGINT for restic with a 15 s grace). The group is killed again after `Wait`, so forked helpers (git-remote-https, ssh, …) never outlive the job. Timeouts are clamped (10 min, or 25 h for `Long`).                                                                                                                                                | `TestTimeoutKillsProcessGroup`, `TestCancelKillsProcessGroup`, `TestBackgroundChildReapedAfterNormalExit`, `TestTimeoutClamped`                                                                                                         |

## 3. Docker Engine API (`internal/docker`)

| Boundary                             | Enforcement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Tests / fuzzers                                                                                                                                                                                                                               |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Socket only                          | The transport `DialContext` ignores the address and always dials the configured unix socket.                                                                                                                                                                                                                                                                                                                                                                                                                                                              | `TestUnixSocketCannotBePointedElsewhere`                                                                                                                                                                                                      |
| Canonical requests                   | `checkRequestShape`, applied before any allowlist on both clients: scheme `http`, host `docker`, no Host override, no userinfo, opaque part or fragment, no percent-encoded path (`RawPath`). The path must be clean (`path.Clean`): no `//`, no `..`, no `\`, no `;`, no control, space or non-ASCII characters, no `/v1.xx` version prefix. The method must be upper-case. Method-override headers are refused. Redirects are never followed.                                                                                                           | `TestEngineAllowlistBypassAttempts` (50 cases: `//containers`, `%2e%2e`, `/v1.47/containers/../exec`, `/v1.47/secrets`, trailing slash, case, absolute URLs, `X-HTTP-Method-Override`, …), `TestRedirectsNeverFollowed`, `FuzzRoundTripShape` |
| Read allowlist                       | GET/HEAD are limited to `/_ping`, `/version`, `/containers/json`, `/containers/{id}/(json\|logs\|stats\|archive)`, `/images/{ref}/json`, `/networks/{name}`, `/volumes/{name}`. No exec, secrets, configs, swarm, plugins, export or image save. The read-only client is GET-only and uses the same list.                                                                                                                                                                                                                                                 | `TestReadOnlyClientAllowlistBypass`, `TestEngineAllowlistLegitimateCalls`, `FuzzAllowedCall`                                                                                                                                                  |
| Write allowlist                      | (method, path) regexes: create image, network, volume or container; start/stop/restart/delete of `idOrName`; wait. Archive upload only into `ppanel-bk-<16hex>` helpers; network delete only for `ppanel-restore-<8hex>`; `v=1` (anonymous volumes) only for `ppanel-restore-<8hex>-db`. A build engine (`build.enabled` set in the local config) adds `/build`, `/build/cancel`, push and delete of `build-<hex12>` tags. The engine never deletes volumes, never uses `force=1` on image delete and never calls `update`, `commit`, `attach` or `exec`. | `TestEngineAllowlist`, `TestEngineAllowlistP6`, `TestBuildEngineAllowlist`, `FuzzAllowedCall`                                                                                                                                                 |
| Ref validation                       | `InspectContainer`, `InspectNetwork`, `InspectImage` and `InspectVolume` validate the reference before building a path.                                                                                                                                                                                                                                                                                                                                                                                                                                   | `TestEngineRefRejection`                                                                                                                                                                                                                      |
| Non-GET only from container handlers | discovery and inventory hold only the GET-only `Client`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | `TestManagedContainersOnly`, `TestNoBuildEngineRefused`                                                                                                                                                                                       |

## 4. Container ownership (`internal/containerops`)

| Boundary        | Enforcement                                                                                                                                                                                                                                                                                                                                                                                                        | Tests / fuzzers                                                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ownership rule  | `IsOwned` requires: `Name == "/"+name`, labels `ppanel.managed=true` and `ppanel.app=<app>` (exact), and a name of `ppanel-<app>-<8hex>`, or `ppanel-<app>-<service>-<8hex>` that matches the `ppanel.service` label. Otherwise `CONTAINER_NOT_MANAGED` and no mutating call.                                                                                                                                      | `TestOwnershipRefusalNoMutatingCall`, `TestComposeOwnershipAndStop`, `FuzzOwnership`                                                                     |
| Name collisions | Names are ambiguous across apps (app `web` + service `api` vs app `web-api`), so labels decide: a container labelled for another app is never owned. Volumes and networks are re-checked by label after `create` (Docker returns an existing object): another app's or a foreign volume → `CONTAINER_NOT_MANAGED`. Residual: a colliding name can be squatted (a denial of service for the other app, not access). | `FuzzOwnership`, `TestRunCandidateRefusesUnmanagedNetworkOrVolume`                                                                                       |
| Label spoofing  | Anyone who can write labels already has Docker (root). This is accepted risk R-01 and documented.                                                                                                                                                                                                                                                                                                                  | —                                                                                                                                                        |
| Hardened create | `CreateBody`/`ComposeCreateBody` hard-code `Privileged=false`, `CapDrop=[ALL]`, the CapAdd allowlist, `no-new-privileges`, `NetworkMode=ppanel-<app>`, `IpcMode=private`, memory/CPU/PID limits, named volumes `ppanel-<app>-<name>` only, and port bindings on `127.0.0.1` only for the route service. There are no binds, devices, or host pid/net/ipc. Images must be pinned by digest.                         | `TestRunCandidateHardenedHostConfig`, `FuzzDecodeRun`, `FuzzDecodeComposeApply` (checks the body invariants for every accepted input), `FuzzDecodeSmall` |

## 5. Nginx path policy (`internal/nginxops`)

| Boundary             | Enforcement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Tests / fuzzers                                                                                                                                    |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lexical policy       | Paths must match `^/etc/nginx/[A-Za-z0-9._/-]{1,200}$`, with no `..` segment, no `//`, and in `filepath.Clean` form. New files only under `ppanel-managed/` (depth ≤ 2) or (P9) `ppanel-gateway/` (depth 1), plus the two include files. Content ≤ 256 KiB, UTF-8, no NUL. At most 20 files and 10 postchecks.                                                                                                                                                                               | `TestDecodeStrictAndLexicalPolicy`, `FuzzValidPath`, `FuzzDecodeNginxParams`                                                                       |
| Filesystem policy    | `EvalSymlinks(parent)` must stay under the real root. A write target must not be a symlink. Creation requires the resolved parent to really be under `ppanel-managed`. `allowedRoots` can only narrow.                                                                                                                                                                                                                                                                                       | `TestPathPolicyRejectsNothingWritten`, `FuzzResolve` (fixture with escape, root, up, loop and dangling symlinks)                                   |
| TOCTOU (check → use) | **All** target-side I/O goes through `internal/safefs`. The resolved directory is opened by walking from `/` with `openat(O_NOFOLLOW\|O_DIRECTORY)`, then `openat`/`renameat`/`unlinkat`/`mkdirat`/`fstatat(AT_SYMLINK_NOFOLLOW)` act relative to that fd. A directory swapped for a symlink after the check makes the operation fail: it never lands outside `/etc/nginx`. This covers reads (`read_files`), candidate writes, created dirs, restore rewrites and removal of created files. | `TestTOCTOUWriteThroughSwappedParent`, `…WriteExisting…`, `…CreateDirs…`, `…Read…`, `…Restore…`, `…RestoreRemove…` (all six failed before the fix) |
| Probes               | Postchecks go to 127.0.0.1 only, with no redirects.                                                                                                                                                                                                                                                                                                                                                                                                                                          | `TestProbeRefusesNonLoopback`, `TestApplyDeadMasterRevertsAndRedirectNotFollowed`                                                                  |

## 6. Builds (`internal/buildops`)

| Boundary        | Enforcement                                                                                                                                                                                                                                                                                      | Tests / fuzzers                                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Build node only | `build.enabled` must be set in the local config; otherwise `NOT_A_BUILD_NODE` before ack.                                                                                                                                                                                                        | `TestNotABuildNodeBeforeAck`                                                                                           |
| Source          | `GIT_URL_RE` (https or git scheme, no userinfo, query, `%` or `ext::`). The host must be in `gitHostsAllowlist` (exact host:port). The commit is 40 hex. Hooks are disabled, redirects are off, there are no submodules or LFS, and the auth header travels only through the `GIT_CONFIG_*` env. | `TestGitHostNotAllowedNoSideEffects`, `TestAuthHeaderNeverInArgvLogsOrResults`, `FuzzDecodeBuild`, `FuzzDecodeInspect` |
| Context         | subdir and dockerfile are relative, with no `..` and no `.git`. `resolveInside` refuses symlinks that escape the checkout. `.git` is excluded. Size ≤ 500 MiB.                                                                                                                                   | `TestBuildTemplateAndSubdir`, `FuzzResolveInside`                                                                      |

## 7. Backups and restores (`internal/backupops`)

| Boundary       | Enforcement                                                                                                                                                                                                                                                                                                    | Tests / fuzzers                                                                 |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Host paths     | `CheckHostPath`: regex, canonical (no `.`/`..`/`//`/trailing `/`), not `/proc`, `/sys` or `/dev`, not under the state dir.                                                                                                                                                                                     | `TestPathsUnderStateDirRefused`, `FuzzCheckHostPath`, `FuzzDecodeBackupParams`  |
| Manifest paths | Every manifest path must pass `CheckHostPath`. `/backup/…` is **no longer an exemption** (`/backup/../etc/shadow` used to be accepted).                                                                                                                                                                        | `TestManifestPathTraversalRejected`                                             |
| Verify hashing | Staging and verify restores hash only files that resolve inside the restore root with no symlink in any component (`safefs.CopyNoFollow`). In-place restores never follow the final component. A restored symlink can therefore not make the agent hash, and report the sha256 of, a file outside the restore. | `TestVerifyFilesNeverFollowsOutOfRoot`                                          |
| Staging dir    | `<stateDir>/restores/<id>` is created through no-follow dir fds: the restores dir must be a real directory, the staging dir must be new, owned by the agent, mode 0700, and resolve to itself.                                                                                                                 | `TestStagingDirRefusesSymlinkedRestoresDir`, `TestRestoreStagingPermsAndVerify` |
| Backup walk    | Manifest hashing opens files with `O_NOFOLLOW\|O_NONBLOCK` and requires a regular file, so there is no symlink swap and no fifo hang.                                                                                                                                                                          | `TestHashFileNeverFollowsSymlink`, `TestManifestHashingAndTruncation`           |
| Credentials    | Credentials are passed only through env (`RESTIC_*`, `PGPASSWORD`/`MYSQL_PWD` in helpers) and are redacted from outputs. The agent's rest-server credential is append-only.                                                                                                                                    | `TestPathsBackupArgvEnvAndSummary`, `TestVolumeBackupHelperHardening`           |

## 8. Redaction and log shipping (`internal/redact`, `internal/logship`)

| Boundary            | Enforcement                                                                                                                                                                                                                                                                                                                                                                              | Tests / fuzzers                                                         |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Shared patterns     | Mirrored exactly from `shared-contracts/src/redaction.ts`.                                                                                                                                                                                                                                                                                                                               | `TestGoldenFile`, `TestPatternNamesMirrorTS`                            |
| Known secret values | Every overlapping occurrence of every value is marked, the ranges are merged and replaced once. This is iterated to a fixpoint together with the patterns (bounded at 8 passes), with fail-closed whole-line replacement if it does not converge. The output never contains a registered value and `Redact` is idempotent. Values that are fragments of `[REDACTED]` are not registered. | `FuzzRedactor` (crasher `pa55word…ghp_…` kept), `TestKnownSecretValues` |
| Line cut            | When a raw line exceeds 64 KiB, a known value straddling the cut is removed: the last `maxKnownLen-1` bytes are dropped and the line is marked truncated.                                                                                                                                                                                                                                | `TestSanitizeSecretStraddlingRawCut`, `FuzzSanitizeAndBatch`            |
| Batches             | ≤ 5000 entries, ≤ 1 MiB gzip, every entry carries all keys, valid UTF-8, lines ≤ 16 KiB.                                                                                                                                                                                                                                                                                                 | `TestShipperBatchLimits`, `FuzzSanitizeAndBatch`                        |

| Boundary            | Enforcement                                                                                                                                                                                                                                                                                                                             | Tests / fuzzers                                                                                                     |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Center endpoints    | Only `https://host[:port]` URLs (no userinfo, query, fragment, path, control characters), ≤ 8, known paths, no duplicates. They are dialled with the same pinned-CA mTLS config as before (no system roots). An invalid enrollment list fails the enrollment; an invalid heartbeat block is ignored.                                    | `TestNormalizeURLAndEndpoints`, `TestInvalidBlocksIgnored`, `FuzzValidateEndpoints`                                 |
| Fail-closed paths   | `private_only` yields no public endpoint in the dial order **and** in the probe set: the agent never connects to a public endpoint under that policy, even with every private endpoint down. A 403 `CONNECTION_PATH_NOT_ALLOWED` marks the path forbidden until a different policy allows it.                                           | `TestPrivateOnlyNeverSelectsPublic`, `TestForbiddenUntilNewPolicyAllows`, `TestP9PrivateOnlyFailsClosedAndRecovers` |
| connection.json     | Written 0600 through `safefs` (temp file + rename in a no-follow dir fd); read without following a symlink, ≤ 64 KiB, re-validated on load (a corrupt file falls back to the enrollment `gatewayUrl`).                                                                                                                                  | `TestStateFileSymlinkRefused`, `TestCorruptStateFallsBack`                                                          |
| Provider metadata   | GET only, no proxy, no redirects, 2 s, ≤ 64 KiB, strict field validation. The URL comes from the local config only (never from the Center).                                                                                                                                                                                             | `TestFetchNoRedirectsTimeoutAndCap`, `FuzzParseDOMetadata`                                                          |
| network.diagnose    | Read-only (no OS config, route or address is changed). TCP targets only in RFC 1918 / 100.64/10 / fd00::/8 or an advertised Center endpoint address; loopback, link-local (cloud metadata) and other public addresses refused before ack; fixed port allowlist ∪ `allowedPorts`; ≤ 10 names, ≤ 20 targets.                              | `TestDecodeDiagnoseRejects`, `TestNetworkJobsValidateBeforeAck`, `FuzzDecodeDiagnose`                               |
| http.probe          | GET/HEAD only; the custom dialer connects **only** to `resolveTo` (private ranges, no loopback/metadata/public); Host/SNI = URL host; no proxy, no redirects, ≤ 1 MiB read (only its sha256 is returned), ≤ 10 s; port allowlist {80, 443, 8080, 8443} ∪ `allowedPorts`; no credentials sent; TLS problems are reported, never trusted. | `TestHTTPProbeHostOverrideNoRedirectBodyCap`, `TestHTTPProbeTLSSNIAndFailures`, `FuzzDecodeProbe`                   |
| Gateway nginx files | The nginx path policy additionally allows **creating** `/etc/nginx/ppanel-gateway/<name>` (depth 1, the real directory, not a symlink) and exactly `/etc/nginx/conf.d/ppanel-gateway.conf`; all other P3 rules are unchanged.                                                                                                           | `TestGatewayFilesCreatableDepthOneOnly`, `TestGatewayRouteDirCreatedAndReverted`, `TestGatewayDirSymlinkRefused`    |

## 10. Dependencies

`go.mod` pins `toolchain go1.26.11`: the Go 1.25 line no longer receives the
net/http, crypto/tls and crypto/x509 fixes. `golang.org/x/sys` is pinned at
v0.47.0, the last version that keeps `go 1.25.0`, which fixes GO-2026-5024
(Windows only). After these changes `govulncheck ./...` reports no
vulnerabilities.

## Known residual risks

- Docker access is equivalent to root (R-01): label spoofing by a local Docker user is out of scope.
- Container, volume and network names can collide across apps (`web`+`api` vs `web-api`). Labels prevent access, but squatting a name blocks the other app.
- The agent's verify, staging and build paths are protected against symlink swaps. restic itself writes into the staging directory and follows its own rules (`--target`).
