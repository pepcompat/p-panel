# pPanel — Feature matrix

Maps `feature_id → screen_id → route → API / MCP tool → agent capability → permission → risk → phase → test IDs → evidence/status`
(brief §13.2, design §12). Status is **TODO** unless evidence exists in `docs/TEST_REPORT.md`.

Notes

- **Screen IDs (`SCR-*`)** are defined here because the design prototype (`design/W3 Server Panel.dc.html`)
  exposes routes but no screen IDs. Design handoff (D10-05) must adopt or remap them (decision D-012).
- **Routes** follow the prototype (`/overview`, `/servers`, `/applications`, `/deployments/new`, `/imports/:scanId`,
  `/monitoring`, `/logs`, `/alerts`, `/backups/:policyId`, `/network`, `/ssh`, `/firewall`, `/plugins`, `/runtimes`,
  `/databases`, `/ai-mcp`, `/approvals`, `/settings/users`). Server-scoped tabs: `/servers/:id/<tab>`.
- **API** paths are relative to `/api/v1`; `PROPOSED` unless marked implemented in `API_CONTRACTS.md`.
- **Permissions** use `API_CONTRACTS.md` §2 constants. **Risk** = read / write / privileged / destructive
  (`SECURITY_THREAT_MODEL.md` §4). Agent capability `—` = Center-only.
- MCP tool names keep the brief's `w3_` prefix (decision D-001).
