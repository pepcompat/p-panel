# pPanel — Security Test Report (P7.01 + P7-T03)

Status: 2026-11-23, Center API / web at the working tree on top of `43feb79` (P6). Scope: Center API
(`apps/api`), agent gateway (mTLS, in-process), web UI (`apps/web`), shared contracts. Agent (Go) code
was dependency-scanned only (owned by another workstream). Threat references: `SECURITY_THREAT_MODEL.md` §3.

## 1. Method

- **Running-code tests** in a new suite `tests/security/**` (`pnpm test:security`). It boots the real
  Nest app through the integration harness (`apps/api/test/integration/helpers.ts`), talks HTTP to it with
  supertest and to the agent gateway over real mTLS, against an **isolated database `ppanel_security`**
  (never `ppanel_test`, the lab or `:4000`). The suite is typechecked (`tests/security/tsconfig.json`).
- **Route inventory** is built from Nest metadata (controller/handler `path`, `method`, `@Public`,
  `@RequirePermission`) and asserted equal to the live Express router stack (142 routes). Every route must
  have a probe in `tests/security/authz/probes.ts`; adding a route without a probe fails the suite.
- **Fixture ("world")**: servers A and B; one row of every scoped resource type owned by server A
  (container / compose / nginx apps, container config, secret, deployment + step, pending deployment,
  nginx revision, job, discovery scan + finding, build config, build (with log), source inspection,
  managed routing, alert rule, incident, auto-deploy policy, webhook delivery, backup repo access, backup
  policy, backup run, restore) plus global objects (server group, notification channel, GitHub
  integration, backup repository, production enrollment, a target user + binding). Every A string carries
  a marker; every A id is a "needle".
- **Principals**: anonymous, global `viewer`, global `deployer`, and three principals scoped to server B
  (`ops_admin`, `platform_owner`, `viewer`).
- **State-change detection**: md5 over every row of every table (`tests/security/lib/db-snapshot.ts`)
  before/after a probe sweep.
- **Canary scan (P7-T03)**: unique canary values for every secret type; afterwards every
  text/varchar/json/jsonb/array/bytea column of every table, every structured log line (captured at
  `debug`), every audit row and every API response body + headers are searched in raw, URL-encoded, hex
  and base64/base64url (3 alignments) form.
- **Static audits** inside the tests: no `$queryRawUnsafe`/`$executeRawUnsafe`/`Prisma.raw` in
  `apps/api/src`; no HTML sinks in `apps/web/src` except the allow-listed nonce'd theme script; webhook
  HMAC comparison is `timingSafeEqual`.
- **Dependencies**: `pnpm audit --prod`, `govulncheck ./...` (apps/agent).

## 4. Areas verified with no finding

Authorization on all 132 non-public routes (coarse + service scope), owner-based self-approval blocks
(deployment, managed routing, nginx revision, restore all compare `createdBy === user.id`), JWT handling
(HS256 only, per-kind audience, issuer, live session + active user on every request), refresh rotation +
reuse detection, MFA replay protection, constant-time comparisons (setup token, scrape token, backup report
token, webhook HMAC), CSRF (only `/auth/*` is cookie-based; `X-CSRF` + SameSite=Strict + CORS allowlist),
LogQL/PromQL templating (no user query language), nginx route template, compose policy, path canonicalisation
on every path-accepting schema, mTLS gateway identity + per-server job ownership, secret storage (no canary
anywhere outside AES-256-GCM envelopes), structured logs (redaction held at debug level), React escaping (no
unsafe sinks), agent health probes (Go: no redirects followed, path concatenated to a fixed host).

## 5. Residual risks

- Center compromise remains fleet compromise (typed handlers + approvals limit, not eliminate) — RISKS R-01.
- zod 3 → 4 migration outstanding (SEC-P7-11); Prisma CLI transitive `deepmerge-ts` (SEC-P7-10).
- The P7-T03 canary scan exercises every secret type through dedicated flows; it does not re-run the whole
  integration suite with canaries injected (the existing specs hard-code their own fixture secrets). The
  agent-side secret fetch (`/agent/v1/tasks/:id/secrets`) is covered by the P4 integration tests, not by the
  canary scan.
- DNS-rebinding pinning is implemented for webhook deliveries and user-supplied registry hosts; git clones run
  on build nodes (agent) against an operator allowlist only.
- In-memory rate limiting (SEC-P7-A5).
